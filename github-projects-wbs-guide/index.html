WBSサンプル操作ガイド

GitHub Projects で WBS を表に並べ、日単位のロードマップで見るまでの画面操作をまとめたガイドです。サンプルは projects/7（非公開）にあります。

画面について：キャプチャは、ログインしていない状態で撮っています。編集できる本人の画面では、ビューの設定を変えたときに Save changes が出るなど、一部の表示が異なります。記述の根拠は、ページ末尾の出典（2026-09-26 確認）と、サンプルで実際に操作した結果です。

先に知っておく前提

画面の操作より先に、データがどこにあって誰に見えるのかを押さえておくと、運用を決めやすくなります。GitHub の公式ドキュメントで確認した内容と、サンプルを作って分かったことをまとめています。

データの置き場所

Issue の実体はリポジトリにある
Project は Issue を参照して並べているだけです。Issue を削除すると、Project の行も、Project に入れていた日付や工数の値も一緒に消えます（サンプルで確認）。リポジトリごと削除した場合の Project への影響は、公式ドキュメントに記載がありません（未確認）。片付けたいだけなら、リポジトリのアーカイブ（読み取り専用、元に戻せる）を使います。
リポジトリなしで作れるのは「ドラフト」だけ
Project の中で直接作るドラフトは、タイトル・本文・担当・自作フィールドを持てます。ただしラベル・マイルストーンは付けられず、担当者に通知も飛びません。サブイシュー（親子関係）も Issue どうしの機能です。WBS の階層を組むなら、Issue を置くリポジトリが必要です。ドラフトは後から Issue に変換できます。
自作フィールドの値は Project 側に入る
開始日・終了日・工数・WBS番号は Issue ではなく Project に保存されます。同じ Issue を2つの Project に入れると、値はそれぞれ別になります。フィールドは1つの Project に50個までです。
Project はリポジトリではなく、個人か Organization に属する
1つの Project に、複数のリポジトリの Issue を混ぜられます。仕事で使うなら、最初から Organization の Project として作るのが無難です。所有者を変えたいときは、コピーで新しい所有者のもとに作り直します。コピーに付いてくるのは、ビュー、カスタムフィールド、Insights、ワークフロー（自動追加を除く）、それにコピー時に選んだ場合のドラフトとその値です。Issue の行、メンバー、リポジトリとのつながりは付いてきません。

権限と見え方

公開・非公開は Project とリポジトリで別々
Project を公開にしても、非公開リポジトリの Issue は、そのリポジトリの権限を持つ人にしか見えません。
Project の権限を与えても、リポジトリの権限は付かない
Project の権限は Read（見る）・Write（編集）・Admin（メンバー管理も）の3段階です。非公開の Project や非公開リポジトリの Issue を見るには、GitHub アカウントと、Project・リポジトリそれぞれの権限が要ります。仕事の WBS は非公開になるはずなので、顧客に見せるなら顧客にもアカウントと招待が必要です。
保存したビューの設定は全員に効く
並べ替えや日付フィールドを変えると、ビュー名の横に未保存の印が付きます。Save changes を押すまで、変更はほかの人には見えません。保存すると、その Project を見る全員の表示が変わります。自分用の見方が欲しいときは、ビューを別に1つ作ります。

見せ方と出力

ロードマップには日付フィールドかイテレーションが要る
ズームは Month・Quarter・Year の3段階です。バーをドラッグすると、開始日・終了日の値が書き換わります。
依存関係は設定できるが、ロードマップに線は出ない
Issue に「blocked by（待ち）」「blocking（待たせている）」を設定でき、ボードなどに Blocked の印が出ます。ロードマップ上で依存を矢印で結ぶ機能は、ドキュメントに記載がありません。
出力は TSV
検索バーの横の View（歯車）から Export view data を選ぶと、ビューの中身をタブ区切り（.tsv）で出力できます。公式ドキュメントに載っている出力はこれだけで、ロードマップを図のまま出力する方法は記載がありません。
ロードマップの日付フィールドだけは画面で設定する
REST API なら、ビューを作るときにレイアウト・フィルタ・表示する列・並べ替え・グループまで指定できます（GraphQL API で指定できるのは、作成時はレイアウトと表示する列、更新時はそれに加えてフィルタまでで、並べ替え・グループは指定できません）。ロードマップにどの日付フィールドを使うかは、どちらの API にも指定する項目がなく、画面で設定します。

WBS表（テーブル）

  1. WBS表を開く

    上のタブ WBS表 を選びます。最初に見えるのは大項目（フェーズ）の5行です。行頭の › を押すと、その下の作業が開きます。親子関係は Issue の「サブイシュー」から自動で組み立てられます。

  2. WBS番号の順に並べる

    列見出し WBS番号 の右にある … を押し、Sort ascending を選びます。同じメニューの Group by values を使うと、その列の値ごとにまとめて表示できます。

  3. まとめて設定するなら View メニュー

    右上の View を押すと、表示する列（Fields）、グループ、並べ替え、階層表示のオン・オフを一か所で変えられます。並べ替えは2項目まで指定できます。

ロードマップ（日単位のバー）

  1. ロードマップを開く（最初はバーが出ない）

    タブ ロードマップ（日単位） を開きます。このサンプルでは、バーに使う日付フィールドが決まっていない状態だったので、右側が空でした。

  2. バーに使う日付を選ぶ

    View → Dates を開き、Start date を 開始日、Target date を 終了日 にします。ツールバーの Date fields からも同じ設定ができます。

  3. 日単位のバーを見る

    ズームが Month なら、1日が1列になります。ツールバーには Today と ‹ › のボタンがあり、表示する期間を動かせます。バーをドラッグすると、開始日・終了日の値が書き換わります。

  4. 全体を見渡すときは Quarter

    View → Zoom level、またはツールバーの Month を押して Quarter に切り替えると、下のキャプチャでは8月下旬から11月下旬まで、約3か月分が1画面に収まっています（目盛りは1週間ごと）。ズームは Month・Quarter・Year の3段階で、週や日の単位はありません。

  5. 設定を保存する

    ビューの設定を変えると、ビュー名の横に未保存の印が付きます。View メニューから Save changes を押すと保存され、この Project を見る全員に反映されます。保存しないうちは、変更はほかの人に見えません。メニューには取り消し用の Discard もあります。

ボードと Issue 側の画面

  1. ボードで状態を動かす

    タブ ボード では、Status ごとに列が分かれます。カードを別の列へドラッグすると Status が変わります。カードには WBS番号・日付・工数と、子の完了数（例：1 / 3）が出ます。

  2. Issue でサブイシューを足す

    Issue を開くと、本文の下に Sub-issues 欄があります。ここで子の作業を作ったり、既存の Issue を子としてつないだりできます。右側の Projects 欄では、この画面のまま Status を変えられます。

  3. 実績ログをコメントで残す（工数記録の方式 B の例）

    日付と時間をコメントで積み上げる書き方の例です。履歴が残る代わりに、合計はスクリプトなどで集計する必要があります。累計だけでよければ、Project の 実績工数(h) に数字を上書きするほうが手軽です。

つまずきやすいところ

親の期間は自動で変わらない

子の終了日を親より後ろにずらしても、親の開始日・終了日の値はそのままでした（サンプルで確認）。数値フィールド（工数など）は、グループの見出しに合計を出せます（Field sum）。

WBS番号はテキスト型

サンプルの WBS番号はテキスト型のフィールドです。テキスト型の並べ替えの規則はドキュメントに記載がなく、「3.10」と「3.2」の並び順は意図どおりにならない可能性があります（未確認）。10件を超える階層は「3.02」のようにゼロ埋めしておくと安全です。

ビューの保存忘れ

並べ替えや日付フィールドを変えたら Save changes を押します。押さないと、ほかの人には変更が見えません。

日程の自動調整は見当たらない

土日・祝日の考慮、ベースライン、依存関係に合わせた日程の自動調整は、公式ドキュメントに記載がありません。遅れたら後ろの作業を手で動かす前提で考えます。

Issue を消すと行も値も消える

Issue の実体はリポジトリにあり、削除すると Project の行と値も消えます。サンプルを片付けるときは、削除ではなくリポジトリのアーカイブにします。
