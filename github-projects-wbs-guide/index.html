WBSサンプル操作ガイド

GitHub Projects で WBS を表に並べ、日単位のロードマップで見るまでの画面操作をまとめたガイドです。サンプルは projects/7（非公開、本人のみ閲覧可）にあります。

画面について：キャプチャはログインしていない状態で撮っています。そのため右上に Sign in が見えます。ログインしている本人の画面では、そこがアイコンになります。また設定を変えたとき、メニューに Save ボタンが出ます。

先に知っておく前提

画面の操作より先に、データがどこにあって誰に見えるのかを押さえておくと、運用を決めやすくなります。GitHub の公式ドキュメントで確認した内容と、サンプルを作って分かったことをまとめています。

データの置き場所

Issue の実体はリポジトリにある
Project は Issue を参照して並べているだけです。リポジトリを消すと、その Issue は Project からも消え、Project に入れていた日付や工数の値も一緒になくなります。片付けたいだけならアーカイブ（読み取り専用、元に戻せる）を使います。
リポジトリなしで作れるのは「ドラフト」だけ
Project の中で直接作るドラフトは、タイトル・本文・担当・自作フィールドを持てます。ただしラベル・マイルストーンは付けられず、担当者に通知も飛びません。サブイシュー（親子関係）も Issue どうしの機能です。WBS の階層を組むなら、Issue を置くリポジトリが必要です。ドラフトは後から Issue に変換できます。
自作フィールドの値は Project 側に入る
開始日・終了日・工数・WBS番号は Issue ではなく Project に保存されます。同じ Issue を2つの Project に入れると、値はそれぞれ別になります。フィールドは1つの Project に50個までです。
Project はリポジトリではなく、個人か Organization に属する
1つの Project に、複数のリポジトリの Issue を混ぜられます。仕事で使うなら、最初から Organization の Project として作るのが無難です。所有者を変えたいときはコピーで作り直しますが、コピーに付いてくるのはビュー・フィールド・ドラフト・ワークフローだけです。Issue の行、メンバー、リポジトリとのつながりは付いてきません。

権限と見え方

公開・非公開は Project とリポジトリで別々
Project を公開にしても、非公開リポジトリの Issue は、そのリポジトリの権限を持つ人にしか見えません。
Project の権限を与えても、リポジトリの権限は付かない
Project の権限は Read（見る）・Write（編集）・Admin（メンバー管理も）の3段階です。見る人・更新する人は全員が GitHub アカウントを持ち、Project とリポジトリの両方に権限が必要です。顧客に見せる場合も同じです。
保存したビューの設定は全員に効く
並べ替えや日付フィールドを変えて Save すると、その Project を見る全員の表示が変わります。自分用の見方が欲しいときは、ビューを別に1つ作ります。

上限

サブイシューは親1つに100件、8階層まで
別のリポジトリの Issue を子にすることもできます。
1つの Project に入る項目は 50,000 件まで
アーカイブした項目も数に入ります。

見せ方と出力

ロードマップには日付フィールドかイテレーションが要る
ズームは Month・Quarter・Year の3段階です。バーをドラッグすると、開始日・終了日の値が書き換わります。
依存関係は設定できるが、ロードマップに線は出ない
Issue に「blocked by（待ち）」「blocking（待たせている）」を設定でき、ボードなどに Blocked の印が出ます。ロードマップ上で依存を矢印で結ぶ機能は、ドキュメントに記載がありません。
出力は TSV
ビュー名の横の ▾ から Export view data を選ぶと、表を TSV で出力でき、Excel でも開けます。ロードマップを図のまま PDF や画像にする機能はありません。
API で作れるのはビューの枠まで
ビューの作成、表示する列、フィルタは API で設定できます。並べ替え・グループ・ロードマップの日付フィールドは、画面で設定するしかありません（サンプルを作って確認）。

アプリは日々の更新に使えます。ロードマップを見たり、ビューを設定したりするのは PC のブラウザで行います。スマホのブラウザでも「PC版サイトを表示」にすれば操作できますが、かなり窮屈です。

WBS表（テーブル）

  1. WBS表を開く

    上のタブ WBS表 を選びます。最初に見えるのは大項目（フェーズ）の5行です。行頭の › を押すと、その下の作業が開きます。親子関係は Issue の「サブイシュー」から自動で組み立てられます。

  2. WBS番号の順に並べる

    列見出し WBS番号 の右にある … を押し、Sort ascending を選びます。同じメニューの Group by values を使うと、その列の値ごとにまとめて表示できます。

  3. まとめて設定するなら View メニュー

    右上の View を押すと、表示する列（Fields）、グループ、並べ替え、階層表示のオン・オフを一か所で変えられます。並べ替えは2項目まで指定できます。

ロードマップ（日単位のバー）

  1. ロードマップを開く（最初はバーが出ない）

    タブ ロードマップ（日単位） を開きます。バーに使う日付フィールドをまだ決めていないので、右側は空です。

  2. バーに使う日付を選ぶ

    View → Dates を開き、Start date を 開始日、Target date を 終了日 にします。ツールバーの Date fields からも同じ設定ができます。

  3. 日単位のバーを見る

    ズームが Month なら、1日が1列になります。Today で今日に戻り、‹ › かトラックパッドの横スクロールで前後に動かします。バーの端をドラッグすると、開始日・終了日の値がそのまま書き換わります。

  4. 全体を見渡すときは Quarter

    View → Zoom level、またはツールバーの Month を押して Quarter に切り替えると、2か月分が1画面に収まります。ズームは Month・Quarter・Year の3段階で、週や日の単位はありません。

  5. 設定を保存する

    ビューの設定を変えると、View メニューの下に Save と Discard が出ます。Save を押さないと、ページを開き直したときに元へ戻ります。保存した設定は、この Project を見る全員に反映されます。

ボードと Issue 側の画面

  1. ボードで状態を動かす

    タブ ボード では、Status ごとに列が分かれます。カードを別の列へドラッグすると Status が変わります。カードには WBS番号・日付・工数と、子の完了数（例：1 / 3）が出ます。

  2. Issue でサブイシューを足す

    Issue を開くと、本文の下に Sub-issues 欄があります。ここで子の作業を作ったり、既存の Issue を子としてつないだりできます。右側の Projects 欄では、この画面のまま Status を変えられます。

  3. 実績ログをコメントで残す（工数記録の方式 B の例）

    日付と時間をコメントで積み上げる書き方の例です。履歴が残る代わりに、合計はスクリプトなどで集計する必要があります。累計だけでよければ、Project の 実績工数(h) に数字を上書きするほうが手軽です。

つまずきやすいところ

親の期間は自動で変わらない

子の日付を動かしても、親の開始日・終了日はそのままです。自動で集計されるのは子の完了数だけです。

WBS番号は文字として並ぶ

「3.10」が「3.2」より前に来ます。10件を超える階層は「3.02」のようにゼロ埋めします。

ビューの Save 忘れ

並べ替えや日付フィールドを変えたら Save を押します。押さないと開き直したときに戻ります。

自動で日程を組み直さない

土日・祝日の考慮、ベースライン、依存関係に合わせた自動調整はありません。遅れたら後ろの作業を手で動かします。

リポジトリを消すと行も消える

Issue の実体はリポジトリにあります。サンプルを片付けるときは、削除ではなくアーカイブにします。
